# Token Scam Patterns Guide — 27 Patterns We Detect

**By AIGEN Protocol SafeAgent Scanner v2.1.0**

This is a reference for AI agents and developers who need to understand crypto token scam patterns. Our scanner checks for all 27 automatically.

## Critical Severity (instant red flag)

### 1. Hidden Mint
**Pattern:** `_mint(` or `mint(` callable by owner after deployment
**Risk:** Owner can create unlimited tokens, dumping the price to zero
**Example:** Token launches, price goes up, owner mints 1B tokens and sells

### 2. Honeypot (Buy-but-can't-sell)
**Pattern:** `require(!_blacklisted[sender])` on transfer, with owner-controlled blacklist
**Risk:** You can buy the token but sells are blocked for everyone except the owner
**Detection:** We simulate a real DEX swap (buy→sell) to verify

### 3. Fake Renounce
**Pattern:** `renounceOwnership()` exists but a hidden `recoverOwnership()` function too
**Risk:** Appears safe (ownership renounced) but owner can reclaim control anytime

### 4. Airdrop Scam
**Pattern:** Free tokens airdropped to wallets, but sell function has `require(!_airdropped[sender])`
**Risk:** You see free tokens in your wallet but can never sell them

### 5. Balance Manipulation
**Pattern:** Custom `balanceOf()` override that returns fake values
**Risk:** Your wallet shows you have tokens, but actual balance is 0

## High Severity

### 6. Unlimited Fee Change
**Pattern:** `setFee()` or `updateTax()` with no max cap
**Risk:** Owner can set buy/sell tax to 99% after you buy

### 7. Blacklist Function
**Pattern:** `blacklist(address)` callable by owner
**Risk:** Your address can be blocked from selling at any time

### 8. Pause Trading
**Pattern:** `pause()` / `unpause()` on transfers
**Risk:** Owner can freeze all trading while they exit through a backdoor

### 9. Max Sell Restriction
**Pattern:** `maxSellAmount` set by owner
**Risk:** Owner sets max sell to 0, nobody can sell

### 10. Anti-Whale with Owner Exemption
**Pattern:** Max transaction limit with `isExcluded[owner] = true`
**Risk:** You're limited to tiny sells, owner can dump unlimited

### 11. Proxy Contract
**Pattern:** `delegatecall` to upgradeable implementation
**Risk:** Contract can be completely rewritten after you buy

### 12. Hidden Fee Receiver Change
**Pattern:** `setMarketingWallet()` or `changeFeeReceiver()`
**Risk:** Fees redirected to owner's new wallet — slow rug

## Medium Severity

### 13-27. Additional Patterns
- Transfer delay (forced wait between transfers)
- Time-locked functions (rug activates after delay)
- Cooldown manipulation
- Swap-and-liquify with excessive percentage
- No reentrancy guard on ETH transfers
- Missing events on ownership transfer
- Hardcoded router address (sandwich attack risk)
- External call in transfer (arbitrary code execution)
- Self-destruct capability
- Approval manipulation
- Supply inflation mechanism
- LP token lock absence
- Fake LP lock (lock contract owned by deployer)
- Trading enable switch (can disable trading)
- Whitelist-only trading period
